# Email-to-Brain: Outlook/IMAP Messages That Update Your Brain

Emails arrive. Brain pages get smarter. The agent reads your inbox via himalaya CLI,
detects entities, updates person and company pages, extracts action items, and files
everything with source attribution.

## IMPORTANT: Instructions for the Agent

**You are the installer.** Follow these steps precisely.

**The core pattern: code for data, LLMs for judgment.**
Email collection is split into two layers:
1. DETERMINISTIC: code pulls emails via himalaya CLI, detects noise/signatures,
   generates retrieval references. This never fails. Timestamps are always accurate.
2. LATENT: you (the agent) read the collected emails and make judgment calls.
   Who is important? What entities are mentioned? What action items exist?

**Do not try to pull emails yourself.** Use the collector script. It handles
pagination, deduplication, MIME stripping, and noise filtering. If you
try to do this via raw himalaya calls, you WILL miss emails or break
deduplication. The collector exists because LLMs kept failing at this.

**Why sequential execution matters:**
- Step 1 validates himalaya is installed and configured. Without it, nothing connects.
- Step 2 sets up the collector. Without it, you have no emails to analyze.
- Step 3 does the first collection. Without data, Step 4 can't enrich.
- Step 4 is YOUR job: read the digest, update brain pages.

## Architecture

```
Outlook/IMAP Account
  ↓ (local IMAP proxy at 127.0.0.1:1993 — already configured)
himalaya CLI
  ↓ envelope list + message read (JSON output)
Email Collector (deterministic Node.js .mjs script)
  ↓ Outputs:
  ├── messages/{YYYY-MM-DD}.json     (structured email data)
  ├── digests/{YYYY-MM-DD}.md        (markdown digest for agent)
  └── state.json                     (last collect date, known IMAP UIDs)
  ↓
Agent reads digest
  ↓ Judgment calls:
  ├── Entity detection (people, companies mentioned)
  ├── Brain page updates (timeline entries, compiled truth)
  ├── Action item extraction
  └── Priority classification (urgent / normal / noise)
```

## Opinionated Defaults

**Noise filtering (deterministic, in collector):**
- Skip: noreply@, notifications@, calendar-notification@
- Flag: DocuSign, Dropbox Sign, HelloSign, PandaDoc (signatures needing action)
- Keep: everything else

**Email accounts:** Configure multiple accounts. Common setup:
- Work email (company domain)
- Personal email (gmail.com)

**Digest format:** Daily markdown with sections:
- Signatures pending (DocuSign etc. needing action)
- Messages to triage (real emails from real people)
- Noise (filtered, available if needed)

Every email gets a baked-in retrieval reference: `` `himalaya message read --account ACCOUNT <id>` `` — generated by code, never by the LLM, so they are always correct and reproducible.

## Prerequisites

1. **GBrain installed and configured** (`gbrain doctor` passes)
2. **Node.js 18+** (for the collector script)
3. **himalaya v1.2.0+** installed and configured with at least one IMAP account
   (`himalaya account list` shows your account)

## Setup Flow

### Step 1: Validate himalaya

Check that himalaya is installed and configured:

```bash
himalaya --version && echo "PASS: himalaya installed" || echo "FAIL: himalaya not found"
himalaya account list && echo "PASS: accounts configured" || echo "FAIL: no accounts found"
```

Himalaya config lives at `~/.config/himalaya/config.toml`. If the account list is
empty, the user must configure an account there before proceeding.

Ask the user: "Which account name should the collector use? (Copy it exactly from
`himalaya account list`)"

Set the account name as `HIMALAYA_ACCOUNT` for the rest of setup.

**STOP until himalaya validates and `HIMALAYA_ACCOUNT` is confirmed.**

### Step 2: Set Up the Email Collector

Create the collector directory and script:

```bash
mkdir -p email-collector/data/{messages,digests}
cd email-collector
npm init -y
```

The collector script needs these capabilities:
1. **collect** — pull envelopes from himalaya (`himalaya envelope list -o json "after YYYY-MM-DD" --account ACCOUNT`), deduplicate by IMAP UID (stored in `state.json`), fetch body via `himalaya message read -o json <id>`, strip MIME markers, store as JSON
2. **digest** — generate a markdown digest from collected emails, grouped by: signatures pending, messages to triage, noise
3. **state tracking** — remember last collection date and known IMAP UIDs (`state.knownMessageIds`) to avoid re-processing

Key design rules for the collector:
- Accept a `--since YYYY-MM-DD` flag (default: yesterday)
- Dedup key is IMAP UID (the `id` field from `himalaya envelope list`); UIDs are stable for practical use on a single account
- `himalaya message read -o json <id>` returns body but NOT Message-Id header; use `himalaya message export --full <id>` (stdout) to parse the RFC 2822 `Message-Id:` header if cross-folder dedup is needed
- Strip `<#part …>` MIME markers from body before storing
- Collect both Inbox and Sent Items (`--folder "Sent Items"`) to detect replied-to threads
- Noise filtering is deterministic: noreply, notifications, calendar invites
- Signature detection uses known patterns: DocuSign envelope, Dropbox Sign, HelloSign, PandaDoc
- All state persisted to `data/state.json` (last collect date, known IMAP UIDs)
- Output is structured JSON (machine-readable) AND markdown digest (agent-readable)
- Retrieval reference in digest: `` `himalaya message read --account ACCOUNT <id>` `` — a shell command, not a URL

### Step 3: Run First Collection

```bash
node email-collector.mjs collect && node email-collector.mjs digest
```

Verify: `ls data/digests/` should show today's digest file.

```bash
cat data/digests/$(date +%Y-%m-%d).md
```

Confirm it contains real emails with himalaya retrieval references.

### Step 4: Enrich Brain Pages

This is YOUR job (the agent). Read the digest. For each email:

1. **Detect entities**: who sent it? Who is mentioned? What companies?
2. **Check the brain**: `gbrain search "sender name"` — do we have a page?
3. **Update brain pages**: if sender has a brain page, append a timeline entry:
   `- YYYY-MM-DD | Email from {sender}: {subject} [Source: Email, {date}]`
4. **Create new pages**: if sender is notable and has no page, create one
5. **Extract action items**: if the email requires a response or action, log it
6. **Sync**: run `gbrain sync --no-pull --no-embed` to index changes

### Step 5: Set Up Cron

The collector should run every 30 minutes:

```bash
*/30 * * * * cd /path/to/email-collector && node email-collector.mjs collect && node email-collector.mjs digest
```

The agent should read the digest on a schedule (e.g., 3x/day: 9 AM, 12 PM, 3 PM)
and run the enrichment flow from Step 4.

### Step 6: Log Setup Completion

```bash
mkdir -p ~/.gbrain/integrations/email-to-brain
echo '{"ts":"'$(date -u +%Y-%m-%dT%H:%M:%SZ)'","event":"setup_complete","source_version":"1.0.0","status":"ok"}' >> ~/.gbrain/integrations/email-to-brain/heartbeat.jsonl
```

## Implementation Guide

These are production-tested patterns. Follow them exactly.

### Noise Filtering (Deterministic)

```
NOISE_SENDERS = ['noreply', 'no-reply', 'notifications@', 'calendar-notification',
                 'mailer-daemon', 'postmaster', 'donotreply']

is_noise(email):
  from = email.from.toLowerCase()
  return NOISE_SENDERS.some(p => from.includes(p))  // substring match
```

Simple substring matching, not regex. `notifications@slack.com` matches because
`notifications@` is in the pattern list. Order doesn't matter.

### Signature Detection

```
SIGNATURE_PATTERNS = [
  /docusign/i, /dropbox sign/i, /hellosign/i, /pandadoc/i,
  /please sign/i, /signature needed/i, /ready for your signature/i,
  /everyone has signed/i, /you just signed/i
]

is_signature(email):
  subject = email.subject || ''
  from = email.from || ''
  return SIGNATURE_PATTERNS.some(p => p.test(subject) || p.test(from))
```

Test BOTH subject AND from. Signature requests come from services that have
"docusign" in the sender address, not just the subject.

### Envelope Enumeration

```
collect(account, since_date):
  query = `after ${since_date}`
  page = 1
  while true:
    envelopes = himalaya envelope list --account account -o json --page page -s 50 query
    if envelopes is empty: break
    for env in envelopes:
      fetch_and_store(account, env)
    page += 1
```

Frame as directional guidance, not implementation specification. An empty array
from `himalaya envelope list` signals end of results — treat it as the loop
termination condition.

### Dedup and Body Fetch

```
fetch_and_store(account, envelope):
  if envelope.id in state.knownMessageIds: return   // already seen (IMAP UID)
  // message read -o json gives body but NOT Message-Id header
  body_raw = himalaya message read --account account -o json envelope.id
  body = strip_mime_markers(body_raw)
  // message export --full gives raw RFC 2822 (stdout); parse Message-Id if needed
  // (optional — use for cross-folder dedup or external reference)
  full_raw = himalaya message export --account account --full envelope.id
  message_id = extract_header(full_raw, "Message-Id")  // RFC 2822; may differ in case
  record = { imap_id: envelope.id, message_id, subject, from, date, body }
  state.knownMessageIds[envelope.id] = { message_id, date: envelope.date }
```

**Why sent mail matters:** Also collect `Sent Items` (`--folder "Sent Items"`).
Without it, the digest shows "awaiting response" on threads you already replied
to. Sent mail acts as a negative filter.

### MIME Marker Stripping

```
strip_mime_markers(text):
  return text.replace(/<#part[^>]*>/g, '').trim()
```

`himalaya message read -o json` returns body text with MIME part markers
(`<#part …>`). Strip these before storing or passing to the LLM.

### Retrieval Reference (replaces Gmail link generation)

```
retrieval_ref(account, imap_id):
  return `himalaya message read --account ${account} ${imap_id}`
```

This is a shell command reference, not a URL. Render it in the digest as a code
span: `` `himalaya message read --account outlook 216520` ``

Generate these in CODE, never by the LLM. References must be 100% reproducible.

### What the Agent Should Test After Setup

1. **Noise filtering:** Send a test email from `noreply@test.com`. Run collect.
   Verify it appears in noise section, not triage section.
2. **Retrieval references:** Copy a `himalaya message read` command from the digest
   and run it. Verify it returns the correct email.
3. **Deduplication:** Run collect twice in 1 minute. Verify no duplicate messages.
4. **Sent mail:** Reply to an email manually. Run collect. Verify the thread is
   marked as replied-to in the digest.

## Troubleshooting

**No emails collected:**
- Check `himalaya account list` shows the configured account
- Check the IMAP proxy is running: `curl 127.0.0.1:1993`

**Date filter returns nothing:**
- Verify `after YYYY-MM-DD` syntax: `himalaya envelope list -o json "after 2026-01-01"`
- Check system clock is correct

**Message-ID dedup not working:**
- Run `himalaya message export --full <id>` and grep for `Message-Id:` header
- `himalaya message read -o json` never includes this header — always use `--full` for RFC 2822 headers
- If `Message-Id` is absent from `--full` output, the composite key fallback (`imap_id + date + subject_hash`) activates automatically

**MIME markers in body:**
- Collector `strip_mime_markers()` handles `<#part …>` tokens
- Verify the body is stripped before writing to `data/messages/`

**Digest is empty but collection ran:**
- Check `data/messages/` for JSON files
- All emails might be filtered as noise — check noise filtering rules
